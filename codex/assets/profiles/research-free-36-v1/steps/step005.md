# Step 5 - c8 코드 커버리지 환경 설치

## 목표

프로젝트에서 c8 CLI를 사용할 수 있는지 확인하고 버전 명령의 결과를 환경 보고서에
기록한다.

## 입력과 산출물

- 입력: `step_archive/step001_preflight.md`
- 필수 선행 항목: `step001`
- 산출물: `step_archive/step005_c8_test.md`
- 네트워크: 패키지 설치가 필요할 때 사용할 수 있다.
- 시각 검토: 필요하지 않다.

## 실행

먼저 1단계 보고서의 c8 disposition을 확인한다. 근거 있는 SKIP이면 이유와 6단계 커버리지 대안을 환경 보고서에 계승한다. 그 외에는 프로젝트 루트에서 다음 명령을 실행한다.

```text
npx c8 --version
```

명령을 사용할 수 없으면 프로젝트의 패키지 관리 방식을 우선한다. npm 프로젝트라면
다음 설치 명령을 독립적으로 실행할 수 있다.

```text
npm install --save-dev c8
```

정상 권한 확인을 유지하며 설치와 버전 확인을 최대 세 번까지만 시도한다. Node.js
호환성 문제나 패키지 해석 오류가 남으면 c8만 `SKIP`으로 기록하고 이유 및 6단계의 러너 커버리지 대안을 명시한다. 이미 1단계에서 근거 있는 SKIP을 기록했다면 재설치를 강제하지 않는다. 실제 측정 커버리지 품질 게이트는 여전히 필수다.

## 환경 보고서

`step_archive/step005_c8_test.md`에 다음 내용을 기록한다.

- c8 버전 명령과 종료 코드
- 확인된 버전
- 설치 또는 재시도 횟수와 최종 결과
- 실패했다면 비밀값이 제거된 오류 범주

## 완료 조건

- `c8-disposition`: 버전 명령이 종료 코드 0인 `OK`, 또는 이유와 6단계 러너 커버리지 대안을 기록한 `SKIP`이다.
- `c8-environment-report`: 환경 보고서가 버전 확인 결과를 기록한다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.
