# Step 24 - Awwwards 조사 충분성 검증

## 목표

23단계 분석이 이후 설계 결정에 충분한지 원본 증거로 독립 검증한다. 실패 항목을
성공으로 바꾸거나 자동 우회하지 않고, `PASS`만 완료로 인정한다.

## 입력과 산출물

- 입력: `step_archive/step016_조사결과_chunk*.md`
- 입력: `step_archive/step020_선정URL.md`
- 입력: `step_archive/awwwards-*.txt` (22단계가 저장한 실제 원본 텍스트)
- 입력: `step_archive/screenshots/research/awwwards-*.png` (22단계의 실제 페이지·상태·viewport 캡처)
- 입력: `step_archive/step023_조사결과_chunk*.md`
- 필수 선행 항목: `step016`, `step020`, `step022`, `step023`
- 산출물: `step_archive/outputs/step024_검증_r1.md`
- 네트워크: FAIL의 구체적 부족 항목을 보완할 때만 정상 권한 확인 아래 제한적으로 사용한다. 승인된 Jev 선택 API도 허용한다.
- 시각 검토: 필수

## 실행 역할

23단계 분석을 만든 역할과 구분된 독립 검증자 역할이 수집 증거를 처음부터 대조한다.
가능한 경우 별도 검증자에게 맡기고 분석 결론을 그대로 전달하지 않는다.
위임 기능을 사용할 수 없으면 현재 실행자가 수집 자료를 기준으로 독립 검토를
순서대로 수행하며, 별도 역할을 위임했다고 기록하지 않는다. 어느 방식에서도 정상 권한 확인은
유지한다.

## 검증 기준

먼저 20단계 선정 URL, 23단계의 인용, 위 입력 패턴에 해당하는 실제 파일을 대조해
이번 24단계 보고서의 입력 manifest를 만든다. 각 원본·캡처의 정확한 경로, SHA-256,
사이트·페이지·상태·viewport와 연결된 분석 축을 기록한다. 앞선 단계가 별도 manifest나
고정 primary 파일명을 만들었다고 가정하지 않고, 없는 경로를 복사본으로 꾸미지 않는다.
시각 검사 기능으로 이 manifest의 필수 스크린샷을 실제로 열어 다음을 평가한다.

- 데이터 기반: 각 결론이 URL, 원본 텍스트와 화면 영역에 연결되는가
- 누락: 프로젝트 특성상 필요한 디자인 요소가 빠지지 않았는가
- 대안 충분성: 각 동적 조사 축에 비교 가능한 근거 있는 대안이 있는가
- 설계 가능성: 장단점과 물리적 제약으로 설계 결정을 내릴 수 있는가
- 추적성: 선정 URL·23단계 분석 인용과 이번 입력 manifest의 실제 원본·캡처 경로가 서로 일치하는가

시각 검사 기능을 사용할 수 없으면 이 단계를 완료하지 않는다. 필수 스크린샷을
실제로 열어 검사할 수 없는 경우도 같다. 사실 주장과 판정은 URL, 출처, 원본 또는 캡처로
추적되어야 하며 누락된 증거를 발명하지 않는다.

## 판정과 bounded 반복

모든 라운드는 동일한 선언 산출물 `step_archive/outputs/step024_검증_r1.md`의
라운드별 섹션에 저장한다. 라운드 1부터 라운드 5까지 필요한 섹션만 순서대로
추가하며 별도 라운드 파일은 만들지 않는다. 파일 앞의 manifest에는 실제 라운드 수,
검증자 방식, 근거 목록, 항목별 `PASS` 또는 `FAIL`, 최종 판정을 기록한다.
최대 5라운드까지만 허용한다.

- `PASS`: 모든 필수 기준이 근거로 충족된 경우에만 이 단계를 완료한다.
- `FAIL`: 완료 증거가 될 수 없다. 부족 유형, 근거와 권장 보완 범위를 기록한다.
- `FAIL` 보고서는 자동으로 다른 단계로 이동하거나 다른 작업을 실행하지 않는다.
- 5라운드 뒤에도 `PASS`가 없으면 남은 실패를 건너뛰지 않고 현재 workflow를
  차단하며 필요한 사용자 조치를 기록한다.

## 현재 시도 안의 보완 수집과 재분석

라운드 1은 기존 증거를 검증한다. FAIL이면 독립 검증자가 부족 항목 ID, 근거, 필요한 사이트·페이지·viewport 또는 분석 항목을 지정한다.
라운드 2~5 전에 작성자는 해당 부족 항목만 보완하고 검증자는 원본부터 다시 대조한다. 근거가 바뀌지 않은 동일 검증만 반복하지 않는다.
분석 깊이 부족이면 기존 증거를 재분석한다. 페이지·viewport 부족이면 기존에 선정된 공개 사이트에서 필요한 자료만 수집한다.
사이트 다양성 부족이면 20단계의 공개 Awwwards 조사 범위 안에서 대체 공개 사이트를 선정하고 선정 근거를 기록한다.
보완은 총 최대 4회, 회당 최대 2개 페이지 방문·원본 요청과 최대 3개 viewport 캡처로 제한한다. 실패·재시도도 이 예산에 포함한다.
기존 20~22단계의 읽기 전용 공개 수집·신뢰 경계와 정상 권한 확인을 유지한다. 새 로그인, 자격 증명 접근, 쓰기 요청, 다운로드 코드 실행 또는 범위 밖 탐색은 승인되지 않는다.
네트워크·시각 도구 또는 권한이 없어 필수 보완을 수행할 수 없으면 INCOMPLETE로 남는다.

기존 16~23단계 파일과 완료 영수증은 불변이다. progress, state, receipt를 되감거나 이전 단계를 실행하지 않는다.
새 증거는 `step_archive/supplemental/step024/<attempt-id>/round-N/` 아래 새로운 경로에만 저장한다.
현재 attempt-id는 workflow가 부여한 값을 사용한다. Claude에서 해당 값이 없으면 보고서에 새 고유 ID를 기록하고 이번 시도 내에서 고정한다.
기존 경로가 있으면 덮어쓰지 않고 현재 시도의 새 경로를 사용한다. 디렉터리의 실제 경로가 작업공간 안인지 확인하고 외부를 가리키는 symlink/junction을 거부한다.

단일 선언 보고서 `step_archive/outputs/step024_검증_r1.md`에 각 라운드를 추가하고 이전 라운드는 고치지 않는다.
보완 manifest에는 attempt-id, 부족 항목 ID, URL, 수집 시각, HTTP 상태, viewport·화면 상태, 실제 파일 경로, SHA-256과 캡처 영역을 기록한다.
각 보완의 재분석에는 원래 결론, 수정 결론, 대안과 장단점, 정확한 원본·이미지 근거를 연결한다. 사실을 관찰하지 않고 생성하지 않는다.
독립 검증자는 신규 필수 이미지를 실제로 열고 원본·hash와 결론을 대조한다.
최종 PASS 섹션에는 기존 증거와 채택한 보완 증거의 정확한 경로·hash, 최종 통합 분석과 조사 축·대안을 확정한다. 보완이 없으면 빈 보완 manifest를 명시한다.
25·29단계 이후 기획·설계·시각 비교는 이 최종 manifest와 통합 분석을 소비하고 원래 23단계 결론만으로 되돌아가지 않는다.
5라운드 후에도 PASS가 없으면 남은 실패를 생략하지 않고 현재 단계를 INCOMPLETE로 유지한다.

## Jev 의미 체크포인트

조사 축 하나의 대안·장단점과 채택 보완 분석이 준비되면 그 설계 결정에 근거가 충분한지 묻는다. Jev 텍스트 판정은 필수 이미지를 실제로 여는 시각 검사를 대체하지 않는다.

현재 작업에서 Jev 사용과 선택한 발췌문의 외부 전송이 승인된 경우 호스트가 자동 호출한다.
기존 승인이 해당 범위를 포함하면 재확인하지 않는다. 단계 도달이나 `TYPESAFE_API_KEY` 존재는 승인이 아니다.
승인이 없거나 서비스가 불가하면 이유를 기존 단계 보고서에 기록하고 독립 검증을 계속한다.

신뢰한 플러그인의 `node "<plugin-root>/scripts/jev-judge.mjs" prepare --workspace ROOT --input -`로 준비한다.
재사용 전 `inspect --workspace ROOT --report PATH`의 상태와 현재 prepare의 `request_hash`, `policy_hash`, `input_hash`, `sources`를 모두 대조한다.
새 호출은 동일 JSON으로 `run --workspace ROOT --input - --allow-network`를 실행한다.
변하지 않은 입력에는 한 배치만 호출하는 호스트 정책을 적용하며 전역 하드 쿼터로 해석하지 않는다.
`unverified`·`stale`는 판정 근거로 쓰지 않고 abstain·낮은 confidence는 호스트가 원본을 검토한다.
승인된 선택 API 예외는 일반 웹 탐색이나 새 자료 수집을 허용하지 않는다.

입력 파일·발췌문 범위, 동의·중복 방지·보고서 검사는 `docs/jev-checkpoints.md`를 따른다.
기존 독립 검증·Acceptance·실제 검사와 완료 writer는 유지한다. Jev 결과나 `current`는 PASS 또는 완료 권한이 아니다.

## 완료 조건

- `sufficiency-verification-round-1`: 선언된 단일 보고서와 전체 라운드 manifest가 존재한다.
- `verification-screenshot-input`: 입력 manifest에 열거된 실제 필수 스크린샷이 존재하고 조사 축·원본과 연결된다.
- `independent-verifier`: 분석자와 구분된 독립 검증 절차와 실제 방식을 기록했다.
- `bounded-verification-rounds`: 라운드가 최대 5개이며 누락된 번호가 없다.
- `pass-verdict`: 최종 판정이 근거 있는 `PASS`다.
- `visual-sufficiency-inspection`: 필수 이미지를 실제로 열어 충분성을 검사했다.

검증 결과를 기록하고 최종 PASS인 경우에만 step025.md로 진행한다.
