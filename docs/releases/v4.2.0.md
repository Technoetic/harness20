# harness20 v4.2.0 — fourteen-stage workflows and offline trials

New Claude Code and Codex runs use `planning-first-14-v1`. The former new-run
stages 3–8 are removed. Necessary environment preparation follows independent
design PASS in stage 2, ownership and encoding contracts belong to implementation
in stage 3, and actual byte checks run with build verification in stage 4.
Quality, independent QA, final regression and Jev checkpoints remain required.
Existing twenty-, thirty-six- and fifty-stage workflows retain their definitions,
historical bodies, state, receipts and recovery. No existing run is renumbered,
reset or initialized by an upgrade. New14 completion requires a contiguous prefix;
refusing an earlier gate cannot leave later steps marked complete.

## Optional offline trials

Explicit prepare, inspect, record and compare commands freeze the selected
profile/generation, source and configuration hashes, evidence and budgets.
Immutable records compare caller-observed metrics under the same conditions.
They invoke no model, network, shell or tools and change no workflow, QA or
receipt authority. A bounded trace export accepts current Codex receipt metadata;
it omits prompts, transcript bodies, commands and authentication. Claude-only
trace sources are explicitly unsupported.

These selected engineering patterns were informed by Apache-2.0
[Tower source](https://github.com/moatai-io/towersource/tree/76268c2969f20ccbea66d6582206c26e81ba7983).
No upstream code or dependency is copied, and no model-effectiveness or business
benchmark result is claimed. See [workflow-trials.md](../workflow-trials.md) for
commands, schemas, evidence rules and the documented filesystem-race limits.

## Upgrade and verification

Update the existing `harness20` plugin through its native host manager. Preserve
old caches, unrelated plugins, activation scopes and explicit project disable
settings. Start a fresh host session to load changed content. Native hook review
and manual trust remain required; installation does not fabricate trusted-hook
receipts or start a live workflow. Existing isolation and permission boundaries
remain in [SECURITY.md](../SECURITY.md).

The [preparation evidence](../verification/2026-10-10-harness20-tower-release.md)
separates the original full local run from its corrective recheck. Exact release
commit CI, canonical Git-blob ZIP checksums, downloaded assets and measured
installation evidence are recorded in the release's
[`verification.json`](https://github.com/Technoetic/harness20/releases/download/v4.2.0/verification.json).
