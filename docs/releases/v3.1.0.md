## OWASP hardening

The additional hardening introduces deterministic registered-tool guards, strict bounded input and physical file reads, automatic original-TOPIC pins for new Claude runs, credential filtering, shared persistent Jev call/byte quotas, minimal child environments, and reviewed dependency integrity gates. Guard watchdog or native runtime failures deny execution without extending the existing time budgets.

Current native browser adapters cannot provide verified all-transport host network isolation. Actual Aside WebRTC and preconnect bypasses defeat a CSP-only boundary; the previous alternative backend's HTTP/WebSocket routing does not provide that host guarantee either. A common dispatcher gate and direct backend gates therefore reject generated output before serving or navigating it, for explicit, environment, automatic and locked selections. Workspace settings and CLI flags cannot opt out. A supported, independently verified host isolation implementation is required to restore this verifier. Historical browser success measurements do not describe the hardened adapters' current capability.

Read `docs/SECURITY.md` for all ten supplied risk mappings, non-applicable vector/training capabilities, and provider/OS deployment responsibilities. The hardening verification is recorded separately in `docs/verification/2026-10-06-owasp-full.md`.
