# harness20 v4.0.0 — planning first and deterministic security

The public name, repository and installed Claude/Codex identities become `harness20`. New workflows begin with planning and run twenty stages. Existing 36/50 histories, profile IDs, archived bodies, recovery and persisted evidence retain their original meanings and bytes.

This major release includes the applicable host controls reviewed against the user's supplied OWASP LLM Top 10 document. The numbered control/evidence mapping is in [SECURITY.md](../SECURITY.md). It is not an OWASP certification or a guarantee of complete secret detection, general OS/network isolation or provider billing ceilings.

Registered tools cannot directly replace canonical host-produced browser/quality measurement JSON or destructively replace its parent directory. Reads and ordinary advisory notes remain available; these unsigned reports are local evidence, not cryptographic producer attestation.

Native generated-HTML browser execution is unavailable until a supported host adapter provides verified all-transport isolation. Common dispatch, environment/automatic/locked selection and each direct backend entry refuse before serving/navigation/dependency execution. Installed browser availability is not isolation evidence. Trusted browser fixtures and fake unit executors are distinct from executing model-generated output.

## Installation migration

Disable `harness36` or `harness50` in its existing scope before enabling `harness20`. Keep earlier caches and sources for rollback. Preserve explicit project disable settings, including projects that already opted out. The installed identity does not automatically rename an old host namespace.

Keep `step_archive/.harness50-codex/`, all profile/schema/protocol identifiers, `harness50.quality.json`, design/routing manifests and `~/.harness36-security/jev-budget`. Name migration must not reset request quota reservations. Historical commands are parser aliases; old plugins are not activated alongside the new one.

Start a fresh host session after installation. Codex skills are `webapp`, `harness20-status` and `harness20-reset`. Inspect `/hooks` and manually review/trust only the exact current definitions; changed hashes require another review. Package installation, preflight and test fixtures do not bypass that native gate or grant execution permission.
